# Arxitektura qoidalari

- Sheet sync `public.sheet_sync_queue` orqali ishlaydi: `expenses`/`incomes` triggeri webhookni uyg'otadi, soatlik cron qolganini yetkazadi.
- Queue sync writes and bot fuel/HR/DPR writes (keyed by chat:message_id) are idempotent per target (spreadsheet+tab) via `public.sheet_sync_ledger` plus one atomic batchUpdate (pasteData + row developer-metadata token); ambiguous writes are resolved by searching the token, never by blind retry — why: retries/timeouts/concurrent flushes must not duplicate rows.
- Expense/income rows carry their source ID (`expenses:<uuid>`/`incomes:<uuid>`) in a hidden «Innosite ID» sheet column; edits (UPDATE trigger only re-flags an existing queue row) update the row found by that ID, and rows without an ID are never re-appended — why: identical business values can be real separate records, so identity is the source ID only.
- Sinxronizatsiya sozlamalari `public.app_settings` da saqlanadi (`sheets_sync_enabled`, `sheets_sync_spreadsheet_id`, `sheets_sync_tab`, `sheets_sync_project_id`, `sheets_sync_webhook_url`), shunda jadval yoki loyihani kod o'zgartirmasdan almashtirish mumkin.
- Google Sheets API chaqiruvlari faqat server tarafda, Lovable connector gateway orqali amalga oshiriladi (`src/server/sheets-sync.server.ts`).
- Telegram xarajat kategoriyalari `PV Olg'a naqd hisobot` Sheet kategoriyalariga normallashtiriladi; `Kunlik dashboard` ro'yxati `A7`/`B7` dagi bitta dinamik FILTER formulasi bilan `G1` sanasiga qarab o'zi chiqadi, shuning uchun sync faqat `Master_Data!A:H` ga yozadi (yordamchi I/J formulalar ishlatilmaydi).
- Telegram bot faqat ikki tur bilan ishlaydi: `expense` va `income`; ombor/zayavka/material qabul oqimlari yangi yozuvlarda ishlatilmaydi.
- Bot AI suhbati uchun manba — `getSheetContext(question)`: butun `Master_Data!A:H` (sanalar `SERIAL_NUMBER` bilan o'qiladi, chunki jadval `Mar-12` ko'rinishida formatlangan) 2 daqiqa keshlanadi, savoldan kalit so'z va sana ajratilib butun baza bo'yicha qidiriladi; solishtirish `spellNorm` orqali (kirill translit, benzin/binzin) bajariladi.
- Botdagi «... kun hisoboti» so'rovlari AI'ga yuborilmaydi: `detectDayReportRequest` sanani aniqlaydi va `buildSheetDayPdf` Master_Data asosida pdf-lib bilan PDF tuzadi (raqamlar AI emas, koddan — aniqlik uchun).
- Expense/income Sheet sync writes only to the project's Master_Data target (`projects.sheet_id/sheet_tab`, fallback `app_settings.sheets_sync_*`); the consolidated all-projects sheet is no longer written and `sheets_consolidated_*` settings are unused data — why: a second target caused partial-coverage stalls and lost rows.
- Telegram menyusi `public.user_bot_permissions` orqali foydalanuvchiga alohida beriladi; CEO menyusida faqat `innoai` ko'rinadi.

- Ovozli funksiyalar (TTS va STT) UzbekVoice.ai API orqali ishlaydi (`AISHA_API_KEY` env), chunki ular oʻzbek tilini aniqroq taniydi.
- Sheets-sync webhook token lives only in `public.internal_secrets` (key `sheets_sync_token`, no RLS policies) and is read via `public.sheets_sync_url()`; Telegram updates are deduplicated by `public.telegram_processed_updates` — why: no secrets in source/migrations, and Telegram retries must not double-write.
- Sheet category = `public.sheet_category_map` (admin-managed, expense/income separate) → keyword rule → "Boshqa" + row in `public.sheet_sync_warnings`; logic is pure in `src/lib/sheet-category.ts` — why: mapping changes without code, unknown categories never block sync.
- Legacy Sheet rows without «Innosite ID» are linked only manually (exact UUID, `public.sheet_legacy_links` audit + ledger `written`); never auto-matched by business fields — why: identical values can be distinct real records.
- Bot fuel/HR/DPR writes go DB-first into `public.bot_sheet_outbox`, then Sheets via ledger; hourly sheets-sync cron retries pending outbox — why: Sheets failure must not lose Telegram data.
- Management signals: pure rules in `src/lib/insights-rules.ts`, persisted in `public.ai_insights` by unique fingerprint (rule+project+period), critical ones sent to Telegram once (`notified_at`); runs in hourly sheets-sync cron — why: deterministic, no duplicate alerts, LLM can be layered on later.
- The `ai-agent` function requires a JWT (verify_jwt=true) and reads data with the caller's own JWT so RLS applies; org-wide roles (admin/ceo/direktor/finans/buxgalter/accountant/pm/project_manager) see all projects, other roles get 403; Telegram internal calls must pass `telegram_user_id` and get that user's roles; service role only for the internal Telegram caller — why: authorization lives in code and RLS, never in the prompt.
- AI agent sends the model only role/topic-relevant tool definitions via pure `supabase/functions/ai-agent/tool-select.ts` (core always, specialist/rare by keywords, ORG_ONLY stripped for PM); `runTool` still executes and authorizes all tools — why: fewer tokens and wrong-tool picks without weakening security.
